# 语义检索优化方向

## 问题

当前语义检索是将用户整句问题直接向量化后进行搜索。但用户问题中包含两类不同成分：

| 类型 | 作用 | 例子 |
|------|------|------|
| **检索词（实体）** | 用于向量搜索定位节点 | 应急保障事件、卫星资源、便携站、巴威台风 |
| **逻辑词（意图）** | 决定查询关系路径 | 是否、怎么样、哪些、申请、调用 |

整句向量化时，逻辑词也会参与向量计算，对检索精度产生噪声干扰。

### 示例

```
问题: "某应急保障事件中是否申请卫星资源"
                      ↓
          整句向量化 → 噪声词 "某""中""是否" 也参与相似度计算
                      ↓
          理想做法: 提取 "应急保障事件" 和 "卫星资源" 分别向量搜索
```

## 当前系统的实际做法

系统中有三种语义相关查询模式：

| 模式 | 检索方式 | 遍历方式 |
|------|---------|---------|
| **语义（固定模板）** | 整句向量化 → top_k | 固定 Cypher 模板 |
| **语义NL** | 整句向量化 → top_k | LLM 生成遍历 Cypher |
| **自然语言** | LLM 直接生成整个 Cypher | LLM 决定全部 |

其中 **语义NL** 模式已经部分实现了"检索→推理"分离的思想：
1. 向量搜索找入口节点（检索）
2. LLM 理解问题 + 入口节点 → 生成遍历 Cypher（推理）

## 优化方向

### 方向 A：实体提取增强（推荐）

```
问题 → LLM 提取关键实体词
   ↓
分别对每个实体词做向量搜索
   ↓
汇总入口节点 → LLM 生成遍历 Cypher
```

- 优点：检索精度更高，减少噪声干扰
- 成本：多一次 LLM 调用
- 复杂度：中等

### 方向 B：整句 + 关键词混合检索

```
问题 → 整句向量搜索（top_k_low）
     → LLM 提取实体 → 实体向量搜索（top_k_high）
     → 合并入口节点
```

- 优点：兼顾语义和精确匹配
- 成本：两次向量搜索

### 方向 C：中文分词过滤

使用 jieba 等工具分词后，过滤停用词，仅对关键实体部分做向量搜索。

- 优点：速度快，无额外 LLM 调用
- 缺点：切词不一定准，实体名可能被切碎

## 当前局限

- top_k 固定为 10，无法查全量
- 整句向量化对短文本/精确名称匹配不够精准
- 无实体识别步骤
